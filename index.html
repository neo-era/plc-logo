📡 Frame Modbus TCP (PLC ↔ Proxy)

Hiển thị raw bytes của mọi frame proxy gửi/nhận với PLC. TX = proxy → PLC, RX = PLC → proxy. Chỉ khả dụng ở chế độ Modbus Local Proxy.
Tổng nhận: 0 · Hiển thị: 0 · Mất kết nối lần cuối: —
Chưa có frame nào. Bật chế độ Modbus Local Proxy và đợi poll cycle đầu tiên.
ℹ️
Buffer proxy giữ 500 frame gần nhất. UI poll /frames mỗi 500ms, render tối đa 300 dòng (cũ nhất bị cắt). MBAP header decode: TID PID LEN UID FC .... Function code thường gặp: 01=ReadCoils, 03=ReadHR, 05=WriteCoil, 06=WriteReg.

🟢 Modbus TCP qua local proxy (khuyến nghị)

ℹ️
Browser không nói được Modbus TCP raw (giới hạn bảo mật). Cách tin cậy nhất: chạy 1 proxy Node.js nhỏ trên cùng PC, browser gọi HTTP localhost → proxy nói Modbus với PLC.

4 bước:

  1. Trong LOGO! Soft Comfort: Tools → Transfer → Configure Modbus Slave → Enable. Đặt IP tĩnh cho PLC (vd 192.168.0.3).
  2. Trên PC (cần Node.js 20+): 
    cd local-proxy
npm install
node proxy.js --plc-host 192.168.0.3
  3. Khi log hiện [modbus] ✓ kết nối ... và [http] sẵn sàng là OK.
  4. Trong tab ⚙ Cài đặt: chọn Chế độ = "Modbus Local Proxy", URL = http://localhost:3001 → Lưu & Test.

Chi tiết: local-proxy/README.md — có hướng dẫn auto-start Windows + troubleshoot.

🔵 Chế độ LOGO! Web Server (thay thế, ít tin cậy)

Nếu không muốn chạy proxy, có thể dùng LOGO! Web Server tích hợp. Lưu ý: API POST /AJAX không được Siemens public, format có thể không khớp với firmware bạn dùng.
  1. Mở LOGO! Soft Comfort → Tools → Transfer → Configure web server.
  2. Bật Enable web server, đặt user name + password (mặc định admin).
  3. Cấp quyền đọc/ghi (Allow access) cho các vùng nhớ I, Q, M, V cần dùng.
  4. Tải file plc.html này vào SD card qua mục User-defined web pages (để tránh CORS), hoặc dùng extension CORS Unblock khi test.
  5. Trong tab ⚙ Cài đặt: chọn Chế độ = "LOGO! Web Server", nhập IP + user/pass.
  6. Nhấn 🔌 Test. Nếu thất bại: mở DevTools Network khi dùng trang gốc của PLC, copy đúng format request, chỉnh hàm plcAdapter.request() trong mã nguồn.

🚀 Deploy server trung tâm (VPS Docker)

# Trên VPS Ubuntu/Debian (cài Docker + Compose trước)
git clone <repo-plc-logo> && cd plc-logo
cp server/.env.example server/.env       # sửa JWT_SECRET, ADMIN_PASS
docker compose up -d

# Truy cập http://<vps-ip>:8080 → đăng nhập admin
# → tab Quản trị → tạo trạm → copy gatewayToken (chỉ hiện 1 lần)

📦 Deploy gateway (RasPi tại trạm)

# RasPi Zero 2W / Pi 4, Node.js 20+, USB 4G dongle stick-mode
cd plc-logo/gateway
npm install
cp config.example.json config.json       # paste stationId + gatewayToken
node gateway.js                           # chạy thử

# Setup auto-start
sudo cp systemd/plc-gateway.service /etc/systemd/system/
sudo systemctl enable --now plc-gateway
journalctl -u plc-gateway -f              # xem log realtime

✅ Production checklist

  1. Đặt Caddy/Nginx reverse proxy trước port 8080 → HTTPS Let's Encrypt + WSS tự động.
  2. Bật TLS_CERT_PATH/TLS_KEY_PATH trong .env để gateway dùng mqtts:// thay vì mqtt://.
  3. Đổi tất cả secret trong .env: JWT_SECRET, ADMIN_PASS.
  4. Thêm fail2ban hoặc rate limit middleware cho endpoint /api/login.
  5. Cấu hình LOGO! Modbus Slave trong Soft Comfort, đặt IP tĩnh, đảm bảo gateway ping được PLC.
  6. Backup định kỳ server/data/plc.db (cron + rsync hoặc restic).
  7. Monitor: gửi alert khi trạm offline >5 phút (qua Telegram bot / email).
  8. PLC không bao giờ phơi port 80/502 ra internet — chỉ LAN nội bộ tại trạm.

🔐 Mô hình bảo mật tổng thể

  • User: bcrypt + JWT 7 ngày, role admin/operator. Chỉ admin tạo/xóa trạm.
  • Gateway: token 24-byte hex sinh ngẫu nhiên, server bcrypt-hash, chỉ trả về 1 lần khi tạo trạm.
  • MQTT ACL: Aedes chặn cứng — gateway STN-A không bao giờ thấy topic của STN-B.
  • PLC: chỉ phơi LAN nội bộ tại trạm. Gateway là điểm cô lập duy nhất giữa PLC ↔ internet.
  • Internal secret: server tự sinh random mỗi lần boot cho MQTT client nội bộ.
